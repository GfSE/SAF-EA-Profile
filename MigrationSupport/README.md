# SAF Mapping Script – User Guide

## 1. Purpose

The SAF Mapping Script supports controlled migration of an Enterprise Architect model.

It supports:

- Package renaming
- Element stereotype migration
- Connector stereotype migration
- Diagram viewpoint migration through `MDGView`
- Dry Run with hierarchical text report
- Apply with automatic rollback file
- GUID-based rollback

## 2. Script Structure in Enterprise Architect

Create the following scripts in EA:

- `SAF_Mapping_Base`
- `SAF Mapping - Dry Run`
- `SAF Mapping - Apply`
- `SAF Mapping - Rollback`

The three Project Browser scripts invoke the base script with the corresponding mode.

## 3. Files Beside the EA Model

The following files are stored in the same folder as the EA model:

```text
DefaultMapping.csv
ProjectMapping.csv
ea_stereotype_diagram_mapping.dryrun.txt
ea_stereotype_diagram_mapping.rollback.csv
```

The last two files are generated by the script.

## 4. Default and Project Mapping

### 4.1 DefaultMapping.csv

`DefaultMapping.csv` contains the generic delivered metamodel mappings.

Example:

```csv
kind;from;to
element;SAF_SystemFunction;SAF_Function
element;SAF_SystemCapability;SAF_Capability
connector;SAF_SystemRequirementRefinement;SAF_RequirementRefinement
diagram;F3_SPRO_View;C3_SPRO_View
```

This file should not be modified for project-specific purposes.

### 4.2 ProjectMapping.csv

`ProjectMapping.csv` contains project-specific extensions and deviations only.

A typical use case is project-specific package renaming.

```csv
kind;from;to
package;Vehicle Functions;Functions
package;Mission Functions;Functions
package;Sensors;Sensor Suite
```

Project-specific element, connector, or diagram mappings may also be added when required.

Example:

```csv
kind;from;to
element;Project_OldFunction;Project_Function
diagram;Project_OldView;Project_NewView
```

## 5. Mapping Priority

The script loads the files in this order:

1. `DefaultMapping.csv`
2. `ProjectMapping.csv`

When `ProjectMapping.csv` contains an entry with the same `kind` and `from` combination, it replaces the default entry.

Example:

`DefaultMapping.csv`

```csv
kind;from;to
element;SAF_SystemFunction;SAF_Function
```

`ProjectMapping.csv`

```csv
kind;from;to
element;SAF_SystemFunction;Project_Function
```

Effective mapping:

```text
SAF_SystemFunction --> Project_Function
```

This allows a project to override a delivered default mapping without changing the default file.

## 6. Supported Mapping Kinds

| kind | Meaning |
|---|---|
| `package` | Rename packages |
| `element` | Change element stereotypes |
| `connector` | Change connector stereotypes |
| `diagram` | Change Applied Metamodel / `MDGView` |

CSV format:

```csv
kind;from;to
```

## 7. Usage

### 7.1 Dry Run

1. Select a package, element, or diagram in the Project Browser.
2. Run `SAF Mapping - Dry Run`.
3. Review the report beside the model.

Generated file:

```text
ea_stereotype_diagram_mapping.dryrun.txt
```

The report contains:

- Object type
- Object name
- Previous value
- New value
- GUID
- Hierarchical indentation similar to the Project Browser
- Summary

Example:

```text
[Package] Functional Architecture
  Name: Functional Architecture --> Conceptual Architecture

  [Diagram] Functional View
    Applied Metamodel: F3_SPRO_View --> C3_SPRO_View

  [Element] Execute Function
    Stereotype: SAF_SystemFunction --> SAF_Function
```

### 7.2 Apply

1. Review the Dry Run.
2. Run `SAF Mapping - Apply`.
3. Verify the model changes.
4. Archive the rollback file.

Generated file:

```text
ea_stereotype_diagram_mapping.rollback.csv
```

### 7.3 Rollback

`SAF Mapping - Rollback` reads the rollback file and restores the previous values using GUIDs.

The current Project Browser selection is not relevant for rollback.

## 8. Processing Scope

### Package Selected

The following content is processed recursively:

- Selected package
- Child packages
- Elements
- Embedded elements
- Connectors
- Diagrams

### Element Selected

The following content is processed:

- Selected element
- Child elements
- Embedded elements
- Connectors
- Diagrams

### Diagram Selected

Only the selected diagram is processed.

## 9. Recommended Workflow

1. Use the delivered `DefaultMapping.csv` unchanged.
2. Add project-specific package mappings to `ProjectMapping.csv`.
3. Execute Dry Run.
4. Review the report.
5. Execute Apply.
6. Verify the model.
7. Archive the rollback file together with the corresponding model state.

## 10. Notes

- The script expects a file-based EA repository.
- Mapping files must be located beside the model.
- `ProjectMapping.csv` is optional.
- `DefaultMapping.csv` is required.
- Many-to-one mappings can be rolled back safely because rollback is GUID-based.
